# Alt+D Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship the approved Q-translate Alt+D chat with real streaming AI and hide/close session semantics.

**Architecture:** Extend the shared engine/adapter with structured chat messages and a separate prompt. A GTK4 single-instance chat process owns an in-memory session, uses the existing task controller and provider settings, and registers a GNOME custom shortcut.

**Tech Stack:** System Python/PyGObject GTK4, Gio.Settings, existing HTTPS SSE/NDJSON transport, X11/XWayland own-window placement.

**Spec:** `docs/superpowers/specs/2026-11-01-alt-d-chat-design.md`

## Global Constraints

- Title Q-translate; selected image 1; hide preserves, × cancels and clears; Esc hides.
- Whole turn 30s, complete key attempt 5s, thinking off, verified key-first fallback and sticky success.
- Never auto-copy or split chat into independent chunks. Preserve existing translation actions.
- History RAM only; private diagnostic logs clear every 24h. No secrets in argv/package/reports.
- Work in the user-authorized existing folder: there is no Git repository, so no worktree/init/commits; keep a manual ledger and snapshot changed files.

## Review Focus

- Late completion after close/new session must not repopulate history or UI.
- Fallback after partial stream must replace its partial text; only complete replies enter history.
- Follow-ups over 400 characters retain full ordered context in one request.
- IME commit and Shift+Enter must not submit; window hide must not lose draft or active turn.
- Shortcut registration preserves other bindings and detects failures; installation requires no Shell logout.
